Meal-Planner → Einkaufsliste · #131-Nachschärfung

Was passiert, wenn ein Gericht zweimal geplant wird?

computeMissingIngredients rechnet Bedarf minus physischen Vorrat (fridge_items) — nicht minus dem, was bereits ungecheckt auf der Einkaufsliste liegt. Wird ein Gericht ein zweites Mal für einen weiteren Tag eingeplant, addiert der erneute Übertrag die volle neue Menge auf die bestehende Zeile, statt nur das echte Delta. Drei gleichwertige Lösungswege, zur Auswahl.

Szenario in allen drei Varianten
  1. Bolognese am Montag geplant. Bedarf 400g Tomaten, Vorrat 100g → Übertrag legt 300g Tomaten auf die Einkaufsliste.
  2. Bolognese zusätzlich für Mittwoch geplant. Gesamtbedarf steigt auf 800g, Vorrat unverändert 100g.
  3. Nutzer öffnet "Fehlende Zutaten" erneut — wie soll die Zeile jetzt aussehen, und was passiert beim zweiten Übertrag?
Variante 1
Verrechnen
"Verfügbar" = Vorrat + bereits ungecheckt auf der Liste. Zeigt immer die echte Restmenge, Übertrag bleibt bei Wiederholung korrekt.

300g (bestehend) + 400g (neu übertragen) = exakt der Gesamtbedarf. Keine Überzählung, kein Zutun nötig.
Variante 2
Nur Warnhinweis
Zeigt weiterhin die volle berechnete Menge, ergänzt um einen Hinweis. Nutzer entscheidet selbst, ob er die volle Menge übernimmt.

Variante 3
Ersetzen statt addieren
Übertrag setzt die Menge auf der Liste neu (Gesamtbedarf minus Vorrat), statt sie zur bestehenden Zeile zu addieren.

Die bestehende Zeile wird auf 700g gesetzt, nicht addiert. Korrekt — aber weicht vom sonst überall geltenden Merge-Add-Verhalten der Einkaufsliste ab.
Rein statischer Vergleich, keine echten Komponenten verändert. Auswahl bestimmt die Umsetzung in shopping-needs.ts und use-shopping-needs.ts — siehe docs/issue-131-missing-ingredients-transfer.md, Abschnitt "Nachschärfung 2".
